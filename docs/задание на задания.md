Посмотри текущий Gradio-интерфейс приложения и оцени его с точки зрения пользовательского сценария.

Логика работы приложения должна быть не “загрузил файл → сразу увидел результат рядом”, а как пайплайн обработки материала:

1. Создание задания на обработку:
   - пользователь выбирает источник: аудио, видео или текст;
   - задаёт параметры обработки, например метод суммаризации;
   - запускает обработку;
   - в системе создаётся задание с идентификатором.

2. Выполнение задания:
   - задание проходит этапы обработки: подготовка файла, ASR/транскрипция, суммаризация, сохранение результата, индексация в базе знаний;
   - пользователь должен понимать, что задание выполняется, видеть текущий/последний статус и не воспринимать интерфейс как зависший.

3. Просмотр готового результата:
   - после завершения результат становится готовой записью;
   - транскрипцию, конспект, темы и структурированный отчёт логичнее просматривать как готовый материал, например через базу знаний;
   - готовый результат не должен выглядеть как просто “правая колонка ответа” рядом с формой загрузки.

Сейчас интерфейс не полностью соответствует этому пайплайну: он выглядит скорее как форма “ввод → вывод”, хотя фактически приложение работает через задания, очередь, воркеры и сохранение результата.

Нужно подумать, как без полной переделки проекта приблизить интерфейс к этой логике.

Основная цель:
сделать так, чтобы интерфейс отражал цепочку:

создать задание → дождаться выполнения → открыть готовый результат.

Не нужно сразу переписывать всё приложение. Сначала оцени текущую структуру и предложи безопасный вариант изменения интерфейса в рамках Gradio.
