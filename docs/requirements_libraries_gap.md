# Gap-анализ требований и библиотек

Документ сверяет требования и технологический стек из курсовой работы с фактическими зависимостями и импортами в репозитории.

Статус после правки: основные `requirements*.txt` уже дополнены недостающими пакетами для текущего кода. Этот документ сохраняет не только список исправлений, но и объяснение, почему они нужны.

## Источники сравнения

- Курсовая: `.workbench/Варков_Курсовая_работа_исправленная (3).txt`, разделы 8-9.
- Спринт: `.workbench/Варков Спринт 1.docx`.
- Код: `gateway/`, `asr/`, `llm/`, `rag/`, `storage/`, `shared/`, `benchmark/`.
- Файлы зависимостей: `requirements.txt`, `asr/requirements.txt`, `llm/requirements.txt`, `benchmark/requirements.txt`, `asr/GigaAM/pyproject.toml`.

## Требования из курсовой

В курсовой заявлены следующие требования:

- локальная работа без обязательной передачи данных во внешние облачные сервисы;
- загрузка аудио- и видеофайлов;
- поддержка форматов `wav`, `mp3`, `mp4`, `mkv`;
- автоматическая транскрипция русскоязычной речи;
- формирование краткого конспекта;
- сохранение транскрипта, конспекта, метаданных, фрагментов и векторных представлений;
- семантический поиск;
- ответы на вопросы по найденным фрагментам;
- локальный веб-интерфейс через браузер;
- обмен структурированными данными в JSON и UTF-8;
- работа на обычном ПК с учётом ограниченной VRAM;
- возможность раздельного запуска компонентов и последовательного использования GPU;
- пригодность к исследовательским экспериментам и сравнению методов.

## Фактическое соответствие требованиям

| Требование | Статус в коде | Комментарий |
| --- | --- | --- |
| Локальная работа | Частично выполнено | Код запускается локально, но первая загрузка моделей GigaAM, `multilingual-e5-small`, pyannote/VAD может требовать интернет и доступ к Hugging Face |
| Нет облачных API | В основном выполнено | LLM через локальный Ollama, RAG локальный; внешние сервисы нужны только для скачивания моделей/датасетов |
| Загрузка аудио | Выполнено | UI принимает аудио, ASR-воркер обрабатывает аудио-расширения |
| Загрузка видео | Не выполнено полностью | UI принимает видео, но ASR-воркер не обрабатывает `.mp4`, `.mkv`, `.avi`, `.mov` из очереди |
| Форматы `wav`, `mp3`, `mp4`, `mkv` | Частично выполнено | `wav/mp3` поддерживаются, `mp4/mkv` в текущем ASR pipeline не подхватываются |
| Проверка формата файла | Частично выполнено | Обработка ограничена расширениями в воркерах, но явной пользовательской валидации форматов мало |
| Транскрипция русской речи | Выполнено | GigaAM используется в `asr/worker.py` |
| Диаризация | Не выполнено как пользовательская функция | В курсовой местами упоминается разметка говорящих, но код сохраняет только текст и временные границы |
| Предобработка аудио/нормализация | Частично выполнено | GigaAM/VAD выполняют сегментацию, но отдельного собственного модуля `audio_processing` нет |
| Суммаризация | Выполнено частично | Есть три публичных метода, но методы из спринта реализованы не все |
| Семантический поиск | Выполнено | ChromaDB + `multilingual-e5-small` |
| Ответы на вопросы | Выполнено | RAG через top-5 чанков и Ollama |
| Показ найденных фрагментов | Частично выполнено | RAG ищет фрагменты, но UI в чате показывает в основном записи-источники, а не конкретные чанки с текстом/таймкодами |
| Хранение транскрипта и конспекта | Выполнено | JSON-файлы в `data/knowledge_base/` |
| Хранение векторов | Выполнено отдельно | Векторы хранятся в ChromaDB, а не в JSON-записи |
| Локальный веб-интерфейс | Выполнено | Gradio |
| JSON и UTF-8 | Выполнено | Основные данные сохраняются в JSON UTF-8 |
| Последовательное использование GPU | Выполнено прототипно | `shared/gpu_coord.py`, `asr.lock`, выгрузка Ollama |
| Исследовательские эксперименты | Частично выполнено | Есть `benchmark/`, но часть скриптов устарела или не совпадает с текущей архитектурой |

## Фактические зависимости по окружениям

### Основное окружение `gradio-env`

Заявлено в `requirements.txt`:

```text
gradio>=5.0
chromadb>=1.0
sentence-transformers
httpx
psutil
```

Фактически основное окружение также импортирует:

- `ollama` через `rag/engine.py` и `benchmark/eval_rag.py`;
- стандартные библиотеки: `json`, `os`, `sys`, `subprocess`, `tempfile`, `uuid`, `shutil`.

Ранее `ollama` отсутствовал в `requirements.txt`, хотя нужен для RAG-ответов из основного процесса. Сейчас пакет добавлен в основной requirements.

### ASR-окружение `asr/.venv`

Заявлено в `asr/requirements.txt`:

```text
-e ./GigaAM
torch
torchaudio
onnxruntime
soundfile
librosa
pyannote.audio
```

Фактически ASR-воркер и GigaAM также требуют:

- `torchcodec`, потому что `asr/worker.py` явно делает `import torchcodec`;
- зависимости GigaAM из `pyproject.toml`: `hydra-core`, `numpy`, `omegaconf`, `onnx`, `sentencepiece`, `tqdm`;
- для longform/VAD по `asr/GigaAM/pyproject.toml`: `pyannote.audio`, `torchcodec`, `numba`;
- системный `ffmpeg` в `PATH`.

Ранее `torchcodec` и `numba` не были указаны напрямую в `asr/requirements.txt`. Сейчас они добавлены, потому что `asr/worker.py` импортирует `torchcodec`, а longform/VAD-сценарий GigaAM может требовать `numba`.

### LLM-окружение `llm/.venv`

Заявлено в `llm/requirements.txt`:

```text
ollama
```

Фактически `llm/summarization.py` для всех методов требует:

- `ollama`.

Для `Semantic-Cluster` дополнительно требуются:

- `sentence-transformers`;
- `scikit-learn`;
- `numpy`.

Ранее документация `docs/archive/about.md` говорила, что `llm/.venv` содержит `ollama`, `sentence-transformers`, `sklearn`, но фактический `llm/requirements.txt` содержал только `ollama`. Сейчас `sentence-transformers`, `scikit-learn` и `numpy` добавлены, чтобы `Semantic-Cluster` не откатывался к `Hierarchical` только из-за отсутствующих зависимостей.

### Benchmark-зависимости

Заявлено в `benchmark/requirements.txt`:

```text
datasets>=2.14
soundfile>=0.12
# openai-whisper опционально
```

Фактические benchmark-сценарии требуют разные окружения:

- `install_golos.py`: `datasets`, `soundfile`, `numpy`;
- `eval_asr.py`: ASR-окружение с GigaAM и `soundfile`;
- `compare_asr.py`: для Whisper нужен `openai-whisper`, `torch`, `soundfile`;
- `eval_rag.py`: основное окружение с `ollama`, `chromadb`, `sentence-transformers`;
- `compare_methods.py`: сейчас импортирует `llm.worker`, но обращается к функциям, которые находятся в `llm/summarization.py`, поэтому скрипт требует исправления.

Ранее `numpy` использовался в `install_golos.py`, но явно не был указан в `benchmark/requirements.txt`. Сейчас он добавлен для воспроизводимости.

## Различия в архитектурных названиях

В курсовой встречаются логические пакеты:

```text
ui
application
audio_processing
transcription
summarization
search
storage
```

В репозитории фактические пакеты называются иначе:

```text
gateway
asr
llm
rag
storage
shared
benchmark
```

Для диплома лучше использовать фактические имена репозитория, а логические названия оставить как архитектурные роли:

- `gateway` = UI + orchestration;
- `asr` = transcription;
- `llm` = summarization;
- `rag` = semantic search + QA;
- `storage` = KB CRUD;
- `shared` = config, logging, GPU coordination.

## Что поправить в тексте диплома

1. Не писать, что поддержка видео полностью реализована, пока ASR-воркер не обрабатывает видео.
2. Не писать, что есть диаризация говорящих, если она не выводится и не сохраняется как результат.
3. Уточнить, что ChromaDB хранит векторный индекс отдельно от JSON-базы знаний.
4. Описывать `Whisper`, `WhisperX`, `FAISS`, `Qdrant` как рассмотренные альтернативы, а не как используемые библиотеки.
5. В разделе зависимостей указать три окружения и причину разделения.
6. В разделе исследовательской части отдельно указать зависимости для экспериментальных методов: `scikit-learn`, `sentence-transformers`, возможно `yt-dlp`.
7. Исправить метрики суммаризации: ROUGE/BERTScore можно оставить в обзоре, но основной протокол должен быть многокритериальным.
