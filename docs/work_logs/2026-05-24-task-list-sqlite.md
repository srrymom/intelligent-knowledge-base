# Список заданий через SQLite

Была проблема: интерфейс создавал одно текущее задание и показывал прогресс только для последнего UUID, поэтому пользователь не видел общий список задач.

Сделали: начали добавлять SQLite-реестр заданий и отдельный список задач в Gradio, чтобы каждая задача имела свой статус и прогресс.

Сделали:
- добавили `storage/tasks.py` с SQLite-таблицей `tasks`;
- добавили хранение заданий в `data/tasks.sqlite3`;
- при создании аудио, видео и текстовой обработки теперь создаётся запись задания;
- статус задания вычисляется по текущим артефактам пайплайна: `queue`, `queue_processing`, `summary/*.progress`, `transcript`, `knowledge_base`;
- вкладка `Транскрипция` заменена на вкладку `Задания`: слева создание задачи, справа список задач;
- прогресс ASR/LLM отображается прямо в каждой строке списка задач;
- добавлены действия обновления списка, удаления выбранного задания из списка и очистки завершённых/ошибочных записей.

Проверили:
- `.\gradio-env\Scripts\python.exe -m py_compile shared\config.py storage\tasks.py gateway\handlers.py gateway\services\tasks.py gateway\ui\tabs\transcription.py gateway\ui\events\transcription_events.py gateway\ui\layout.py gateway\ui\theme.py`
- создание/чтение/рендер/удаление тестовой SQLite-задачи через `storage.tasks` и `gateway.services.tasks`;
- сборку новой вкладки в тестовом `gr.Blocks` без запуска воркеров.

Итог: появился отдельный SQLite-список заданий, который обновляется таймером и показывает живой прогресс всех задач, а не только последнего запущенного файла.

Что осталось: кнопка перехода из готового задания прямо к записи в базе знаний пока не добавлена; сейчас в деталях выбранного задания показывается UUID готовой записи.

Возникла проблема: после проверки UI остался запущен в фоне на порту `7860`, а после остановки остался stale `data/gateway.pid`.

Сделали: остановили фоновые процессы `gateway/app.py`, проверили что порт `7860` свободен, удалили stale `gateway.pid`. ASR/LLM-воркеры не трогали, потому что тестовая задача уже была завершена.

Сделали: убрали отдельный выбор задания из вкладки `Задания`. Теперь все задачи сразу отображаются как полноценные `task-row`: в строке видны статус, UUID, источник, параметры, прогресс и UUID записи в базе знаний для готового результата.

Возникла проблема: после создания задания журнал активности в интерфейсе мог визуально отставать, хотя backend продолжал писать ASR/LLM-события в `data/activity.log`.

Сделали: привязали обновление `activity_log_box` к созданию задач, ручному обновлению списка и таймеру списка задач, чтобы журнал обновлялся вместе с task-row.

Возникла проблема: ASR/LLM-воркеры могли быть уже запущены singleton-процессами из старой консоли, поэтому новая консоль `gateway/app.py` видела только UI-события, хотя воркеры продолжали писать подробные события в `data/activity.log`.

Сделали: добавили в gateway фоновый tailer `data/activity.log`, который печатает ASR/LLM/RAG-события в текущую консоль запуска. Для новых дочерних воркеров gateway передаёт `LOG_TO_CONSOLE=0`, чтобы консольный вывод не дублировался.

Проверили:
- повторно прогнали `py_compile` по изменённым модулям;
- проверили рендер списка задач через `refresh_task_ui()`;
- проверили сборку вкладки в тестовом `gr.Blocks` и отсутствие компонентов `task_select` / `task_detail_html`.

Для отчета: интерфейс переведён ближе к пайплайну обработки: пользователь создаёт задание, видит его в общем списке и отслеживает этапы ASR/LLM через прогресс-бары, связанные с SQLite-реестром задач.
