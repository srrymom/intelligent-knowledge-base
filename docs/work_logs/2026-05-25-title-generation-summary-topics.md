# Генерация названия по summary и topics

Была проблема: генерация названия для записей KB иногда возвращала мусорные значения вроде `FreedomPhilosophyDB`, потому что старый подход был слишком хрупким и мог опираться на неудачный выход LLM или начало транскрипта.

Сделали: переделали генерацию title в [llm/summarization.py](/D:/desktop/kursach/prototype/llm/summarization.py:410), чтобы она строилась по `summary_text` и уже извлечённым `topics`, без опоры на первые фразы транскрипта.

Сделали: поменяли порядок в `summarize_transcript()` — теперь сначала извлекаются `topics`, потом строится `title`.

Сделали: заменили старую `build_title(summary_text)` на `build_title(summary_text, topics)`. Теперь LLM просим вернуть 3 варианта названия по одному на строку, затем очищаем строки и берём первый вариант, который проходит валидацию.

Сделали: убрали эвристики, которые использовали начало транскрипта как источник названия, и оставили fallback только из `topics`: две темы → объединённое название, одна тема → она же, иначе `Конспект лекции`.

Сделали: усилили фильтрацию плохих названий. Отбрасываются варианты с латиницей, CamelCase, служебными хвостами вроде `DB/Base/Baze/Freedom/Lecture/Course`, однословные и слишком общие названия.

Возникла проблема: в проекте остался живой LLM worker как отдельный процесс, поэтому после правки файла старый процесс мог продолжать работать со старым кодом в памяти и по-прежнему выдавать старые мусорные title.

Проверили: `python -m py_compile llm\\summarization.py`

Итог: логика генерации title упрощена и теперь зависит только от смысла конспекта и тем. Для применения правки к новым обработкам нужен перезапуск LLM worker.

Что осталось: при необходимости отдельно доработать shutdown воркеров при закрытии gateway, чтобы старые процессы не переживали закрытие UI.

## Для отчета

Упростили генерацию названий KB-записей: убрали зависимость от начала транскрипта, перенесли основу на `summary + topics`, добавили более строгую фильтрацию мусорных названий и fallback из тем без новых зависимостей и без роста потребления RAM/VRAM.
