# Обрезка аудио при загрузке

Была проблема: при загрузке аудио в приложение распознавались только первые примерно две минуты записи.

Разобрались с причиной: в интерфейсе загрузка аудио была сделана через `gr.Audio` с `sources=["microphone", "upload"]`. Этот компонент в Gradio предназначен не только для загрузки файла, но и для записи/редактирования аудио. При `type="filepath"` он может передавать в backend уже не исходный файл пользователя, а временный обработанный файл компонента. На реальной задаче в очередь попал MP3 длительностью `125.808` секунды, поэтому ASR распознал ровно этот короткий файл. То есть ASR и `ffmpeg` не резали длинную запись: до них уже доходил двухминутный временный файл.

Сделали: разделили два сценария ввода аудио.

Сделали:
- для загрузки аудиофайлов заменили `gr.Audio` на `gr.File`, чтобы в очередь копировался исходный файл без аудио-редактора Gradio;
- запись с микрофона оставили отдельным `gr.Audio`, но без редактирования;
- обработчик создания аудиозадачи теперь берёт либо загруженный файл, либо запись с микрофона;
- при постановке медиа в очередь добавили диагностику через `ffprobe`: длительность и размер файла пишутся в `data/activity.log`.

Возникла проблема: одна задача зависла в `data/queue_processing`. ASR-воркер успевал забрать файл из `queue`, но если в этот момент GPU был занят LLM, файл оставался в `queue_processing`, а следующий цикл воркера смотрел только `queue` и не возвращался к уже забранному файлу.

Сделали: ASR-воркер теперь перед просмотром новых файлов также подхватывает аудио из `queue_processing`. Поэтому файл, уже перемещенный в обработку, не теряется при ожидании GPU.

Проверили:
- `gradio-env\Scripts\python.exe -m py_compile gateway\handlers.py gateway\ui\tabs\transcription.py gateway\ui\events\transcription_events.py`
- `asr\.venv\Scripts\python.exe -m py_compile asr\worker.py`
- перезапустили gateway и воркеры;
- застрявшая задача `e5a75c3f-a5bd-417a-9b0a-6def8c395603` была подхвачена из `queue_processing`, прошла ASR и LLM, результат записан в `data/knowledge_base/`.

Итог: загрузка аудиофайлов больше не проходит через редактируемый `gr.Audio`, поэтому длинный файл должен попадать в очередь полностью. В журнале теперь видно фактическую длительность файла на входе, а ASR-очередь устойчивее к ситуации, когда GPU временно занят LLM.

Что осталось: для окончательной проверки нужно загрузить новый длинный файл через поле `Загрузка аудиофайла` и убедиться по строке `duration=...s` в журнале, что в очередь попала полная длительность.

Для отчета: устранена причина распознавания только первых двух минут аудио: загрузка файлов переведена с редактируемого `gr.Audio` на `gr.File`, добавлена диагностика длительности входного медиа и исправлено зависание задач, уже перемещенных ASR-воркером в `queue_processing`.
