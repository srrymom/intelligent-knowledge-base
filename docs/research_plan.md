# План исследовательской части

Документ задает исследовательскую рамку ВКР: вопросы, гипотезы, методы сравнения и ожидаемые таблицы результатов.

## Исследовательский вопрос

Какие методы суммаризации длинных русскоязычных ASR-транскриптов лекций лучше сохраняют темы, понятия, определения, примеры и фактическую точность при работе с малой локальной LLM и ограниченной видеопамятью?

## Подвопросы

1. Дает ли LLM-суммаризация заметный выигрыш по учебной полезности по сравнению с extractive baseline?
2. Лучше ли Hierarchical-суммаризация сохраняет содержание длинных лекций, чем Map-Reduce?
3. Помогает ли тематическая группировка получить более удобный учебный конспект, даже если порядок исходной лекции меняется?
4. Снижает ли evidence-aware подход потерю фактов и галлюцинации при финальном слиянии?
5. Какие метрики лучше согласуются с экспертной оценкой качества конспекта?
6. Как меняется стоимость методов: время, число LLM-вызовов, устойчивость к OOM, требования к VRAM?

## Гипотезы

H1. Extractive/MMR будет лучше сохранять фактическую опору на источник, но проигрывать LLM-методам по читаемости и структуре.

H2. Hierarchical будет стабильнее Map-Reduce на длинных лекциях, потому что ограничивает размер каждого merge-запроса.

H3. Semantic-Cluster может улучшить тематическую структуру конспекта, но требует отдельной оценки, не завязанной на порядок исходного текста.

H4. Evidence-Hierarchical должен повысить фактическую точность и покрытие ключевых элементов за счет возврата к исходным фрагментам при слиянии.

H5. Одна автоматическая метрика не даст корректного ранжирования методов; нужна комбинация coverage, source-grounded проверки, QA-полезности, экспертной рубрики и стоимости.

## Методы для сравнения

| Метод | Роль в исследовании | Статус |
| --- | --- | --- |
| Extractive/MMR | baseline без LLM-генерации | нужно реализовать |
| Map-Reduce | простой LLM baseline | частично реализовано |
| Hierarchical | основной стабильный baseline | реализовано |
| Semantic-Cluster | тематический подход | реализовано в базовом виде |
| Evidence-Hierarchical | исследовательская модификация | нужно реализовать |
| Sequential/Refine | линейный multi-pass | опционально |
| Coarse-to-Fine | двухпроходный план + детализация | опционально |

В дипломе важно разделять реализованные методы и методы из обзора литературы. RAPTOR, GraphRAG, G-Eval, LongLLMLingua и похожие подходы можно обсуждать в обзоре и перспективах, если они не были честно реализованы и прогнаны в одинаковых условиях.

## Корпус данных

Минимальный корпус:

- 6 лекций: 2 короткие, 2 средние, 2 длинные;
- русский язык;
- разные предметные области, если получится: математика, физика, информатика или смежные учебные материалы;
- для части лекций можно использовать YouTube-субтитры как источник текста;
- для демонстрации полного pipeline нужно отдельно прогнать аудио или видео через ASR.

Сильный корпус:

- 9-12 лекций;
- баланс по длине и предметным областям;
- отдельное сравнение "чистые субтитры" против "ASR-транскрипт";
- сохранение исходных файлов, транскриптов, конспектов и метаданных эксперимента.

## Разметка лекций

Для каждой лекции нужна небольшая ручная разметка:

- список ключевых тем;
- список понятий и терминов;
- определения, которые должны быть сохранены;
- примеры, кейсы, формулы или алгоритмы;
- 5-10 контрольных вопросов;
- при возможности: таймкоды или фрагменты-источники для ключевых элементов.

Разметка не должна быть идеальной академической аннотацией. Для ВКР достаточно фиксированного формата и одинаковых правил для всех методов.

## Экспериментальный протокол

1. Подготовить корпус и разметку.
2. Зафиксировать окружение: GPU, RAM, модель ASR, модель LLM, `LLM_NUM_CTX`, версии зависимостей.
3. Для каждой лекции сформировать единый транскрипт.
4. Прогнать все методы суммаризации на одинаковом входе.
5. Сохранить результаты в JSON/Markdown вместе с метаданными запуска.
6. Посчитать автоматические метрики.
7. Провести ручную проверку покрытия и фактичности по разметке.
8. Заполнить экспертную рубрику.
9. Сравнить методы по качеству и стоимости.
10. Разобрать ошибки: потеря темы, искажение определения, галлюцинация, повтор, плохая структура, OOM или слишком долгое выполнение.

## Ожидаемые таблицы в дипломе

Таблица 1. Сравнение методов суммаризации по принципу работы, плюсам, минусам и требованиям к ресурсам.

Таблица 2. Состав корпуса: лекция, предметная область, длина, источник, число слов, способ получения транскрипта.

Таблица 3. Автоматические метрики: compression ratio, term/concept coverage, redundancy, rough faithfulness, time, LLM calls.

Таблица 4. Source-grounded оценка: topic coverage, concept coverage, definition coverage, example coverage, QA answerability, claim support.

Таблица 5. Экспертная рубрика: полнота, точность, структура, читаемость, полезность, отсутствие повторов.

Таблица 6. Итоговое ранжирование и компромиссы: лучший по качеству, лучший по скорости, лучший по фактичности, лучший для локального продукта.

## Ожидаемый вывод

Вероятный вывод не обязан быть "один метод победил всегда". Более реалистичный и сильный вывод: разные методы оптимизируют разные свойства. Для локальной системы обработки лекций метод нужно выбирать по профилю: полнота учебных элементов, проверяемость по источнику, читаемость, структура и вычислительная стоимость.
